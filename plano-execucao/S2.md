## Issue #13 — abrirPts + transicionarStatusPts

Usecases em `src/server/care-plan/pts.ts`:

- `abrirPts({ pacienteId, refProfissionalId? })` → cria PTS `EM_AVALIACAO`, `versao = 0`, `cerId` do usuário logado. Regra: **um PTS ativo por paciente** (existindo PTS não-FECHADO → recusa com mensagem clara). Auditoria na mesma transação.
- `transicionarStatusPts({ ptsId, para, motivo?, version })` → máquina de estados: `EM_AVALIACAO → PACTACAO → SEGUIMENTO → REAVALIACAO → EM_AVALIACAO | FECHADO`. Transição inválida → erro listando as válidas. `FECHADO` exige `motivoEncerramento` + seta `encerramentoEm`. Lock otimista (`versao`) → conflito = 409. Auditoria same-tx com before/after.
- Server actions com zod + permissões: abrir → `recepcao.paciente.cadastrar` OU `triage.triagem.escrever`; transicionar → `care-plan.pts.revisar` (qualquer transição) / `care-plan.pts.encerrar` (para FECHADO).
- **Seed**: adicione bloco marcado `// ===== exemplo painel/dashboard (issue #16) =====` criando 1 paciente + 1 PTS ativo (EM_AVALIACAO) e, se útil, um PTS FECHADO — upsert idempotente, usando os CPFs de teste de `src/server/integrations/sources/mock.ts` se já existirem (senão, CPFs válidos fixos).

**Aceite**: duplicado recusado; transição inválida recusada; FECHADO sem motivo recusado; auditoria same-tx; versão velha → 409.

## Issue #25 — Eventos de cuidado

**Migration nova** — adicione ao `prisma/schema.prisma` (respeite convenções do arquivo):

```prisma
enum TipoEventoCuidado {
  SESSAO
  FALTA
  CANCELAMENTO
  OUTRO
}

model EventoCuidado {
  id              String           @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  ptsId           String           @db.Uuid
  tipo            TipoEventoCuidado
  data            DateTime         @db.Timestamptz(3)
  observacao      String?
  registradoPorId String           @db.Uuid
  criadoEm        DateTime         @default(now()) @db.Timestamptz(3)

  pts           Pts     @relation(fields: [ptsId], references: [id], onDelete: Restrict)
  registradoPor Usuario @relation("eventosRegistrados", fields: [registradoPorId], references: [id], onDelete: Restrict)

  @@index([ptsId, data])
  @@map("evento_cuidado")
}
```

Adicione também as back-relations: em `Pts` → `eventos EventoCuidado[]`; em `Usuario` → `eventosRegistrados EventoCuidado[] @relation("eventosRegistrados")`.

- Server action `registrarEvento` (zod): ptsId, tipo, data, observacao?. Permissão: `care-plan.pts.revisar` OU `clinical.avaliacao.escrever`. `FALTA` → alerta simples visível no header/painel para o ref profissional (notificação real é Fase 2). Auditoria same-tx.
- Timeline do painel (#16): inclua os eventos de cuidado.

**Aceite**: evento salvo FK RESTRICT; FALTA destaca alerta; auditoria; aparece na timeline.
